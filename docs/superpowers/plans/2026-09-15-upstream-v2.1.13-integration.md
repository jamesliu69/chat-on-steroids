# Upstream v2.1.13 Integration Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Merge upstream commit `20198dd2b086a4af7525e131ae2a0e82579d1840` into the fork while preserving every existing fork feature and correcting three known Skills contract gaps.

**Architecture:** Use a real two-parent merge on a local integration branch so upstream authorship and fork history remain intact. Resolve conflicts at the existing owners, keep local-only headless/portable/Traditional-Chinese/security behavior, and add targeted regressions before changing the imported Skills behavior.

**Tech Stack:** Electron, TypeScript, Vitest, Chromium extension JavaScript, PowerShell, Git

**Spec:** `AGENTS.md`, `docs/release-notes/v2.1.13.md`, `docs/skills.md`, and upstream commit `20198dd2b086a4af7525e131ae2a0e82579d1840`

## Global Constraints

- The `upstream` remote is permanently read-only; this integration creates no upstream state and performs no push.
- Preserve fork-only Raspberry Pi/headless server, Windows portable packaging, Traditional Chinese default locale, request-identity hardening, fork download URLs, and CI behavior.
- App, extension, and declared application version must agree on `2.1.13`; bridge protocol remains the version declared by the integrated upstream source.
- Selected Skills and authored text remain complete within 96,000 UTF-16 characters and the transport UTF-8 byte limit; project `AGENTS.md` may be shortened only with an explicit notice.
- `/skills` is Core-only and must not grant capabilities, execute scripts, escape the managed root, or replace the learned project workspace.
- Preserve upstream contributor credit and the original two-parent ancestry.
